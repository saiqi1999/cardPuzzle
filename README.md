# cardPuzzle｜异语药铺（暂定名）

> GDD v0.1 · 2026-10-08  
> 引擎：Cocos Creator 3.x + TypeScript。  
> 定位：结合《巴别塔圣歌》式语言破译与《堆叠大陆》式卡牌堆叠的西幻药铺经营游戏。  
> 首版目标：当天完成一版能运行、能完成完整循环、便于继续迭代的最小原型。本文描述完整设计目标；当前已实现单张 NPC 卡牌交互原型，完整经营循环尚未实现。

玩家经营一家接待不同西幻种族的药铺：看不懂顾客的文字，就从手册与情境中推断需求；理解需求后，通过购买素材、堆叠加工和分步炼制交付药水。赚钱维持经营，积累语言知识，逐步理解更多顾客。


**运行当前卡牌原型**

使用 Cocos Creator **3.8.8** 打开仓库根目录，等待资源导入，打开 `assets/Main.scene` 后点击预览。现有 Canvas 已绑定 Main 和全部 SpriteFrame，无需手动创建节点。运行时自动生成一张 250×350 NPC 卡，可悬停放大、拖动、点击切换需求气泡；拖动不会触发点击。卡牌主体限制在 Canvas 内。

脚本目录：`assets/script/Main.ts`；`assets/script/card/CardData.ts`、`CardView.ts`、`CardDrag.ts`。修改 `DEMO_CARD` 可更换名称与测试符号顺序。图片在 Main 的 Inspector 中绑定，需求符号顺序为 alpha_1、alpha_flower、alpha_fire。像素素材已设为最近邻过滤。

当前卡牌由脚本生成，尚未制作独立 prefab。人物白底保留，画像裁切在卡框内；符号仅为测试组合，不代表正式词义。不包含药水合成、手册或存档。小于卡牌本体的窗口无法完整容纳卡牌，建议桌面横屏预览。

验收：卡片和符号完整显示；移入放大、移出恢复；从人物或文字处均能拖动；松开后停留；四边不越界；点击开关气泡；拖动或取消触摸不打开气泡。当前提交通过 TypeScript 语法转译与场景资源引用检查，尚需在 Cocos 编辑器中完成实际预览验收。

## 一、游戏实体概念解释

| 实体 | 概念与交互 | 首版范围 |
| --- | --- | --- |
| 主面板 | 药铺桌面。卡牌可拖动、堆叠、分离；显示金币、声誉、当前顾客与商店入口 | 单桌面，无地图与场景切换 |
| 设施卡 | 可重复使用的加工工具。素材堆到设施上，满足配方后开始处理；完成后设施保留 | 研钵、炼药锅各一张，开局提供 |
| 素材卡 | 原料、加工中间物和成品药水统一归入素材卡；参与加工时消耗，产出新卡 | 三种药材、清水、三种药粉、三种药水 |
| NPC卡 | 来店的顾客，包含种族、未知文字需求、情境线索和订单判定；药水拖到NPC上交付 | 精灵、矮人两种族；同时只接待一人 |
| 解密手册 | 随时打开的侧栏，包含图文线索、词义猜测、已确认词义和制药步骤；关闭后回到桌面 | 图文书页、候选词义选择、确认状态 |
| 种族文字 | 每个种族拥有独立且稳定的符号—词义对应。同义词跨种族不共用文字 | 每族三个药效词；不做语法、长句与程序化语言 |
| 书页 | 提供可推理的证据，例如受伤者饮药前后的图像，旁边重复出现某个符号 | 开局线索页与两张进阶页 |
| 金币 | 购买素材的经营资源，成功交付后获得报酬 | 初始20金币；三种药材各2金币，清水1金币 |
| 声誉 | 记录误诊代价，失败下降、成功恢复，影响订单收益 | 初始3，上限5；死亡减1，成功加1 |

**首版建议内容与配方：**

| 药水 | 原料 | 步骤 | 用途 |
| --- | --- | --- | --- |
| 治愈药水 | 赤叶草 + 清水 | 赤叶草放入研钵 → 赤叶粉；赤叶粉与清水放入炼药锅 → 治愈药水 | 治疗伤口 |
| 解毒药水 | 月露花 + 清水 | 月露花放入研钵 → 月露粉；月露粉与清水放入炼药锅 → 解毒药水 | 解除中毒 |
| 抗寒药水 | 火根 + 清水 | 火根放入研钵 → 火根粉；火根粉与清水放入炼药锅 → 抗寒药水 | 抵御寒冷 |

以上名称、数值均为原型初值，后续以试玩调整。

**堆叠规则：**

- 素材拖到设施上吸附；配方齐备后显示2秒加工进度。加工时锁定参与卡牌，避免重复消耗与重复产出。
- 研钵每次处理一份药材；炼药锅每次处理一份药粉和一份清水。多余卡牌不加入本轮加工。
- 不支持的组合只提示“无法处理”，不扣材料；素材之间可叠放，但不会凭空触发合成。
- 开始加工前可拖走素材；完成后消耗输入并生成输出，设施可再次使用。
- 将成品拖到NPC卡上显示交付确认，确认后才判定并消耗药水，避免误拖直接造成死亡。

**手册与解谜规则：**

- NPC对白先展示种族符号，不直接显示药水中文名。肖像、动作和随身物品提供辅助证据。
- 玩家通过手册给符号填写候选词义；猜测显示为“待验证”，NPC对白可展示对应猜测。
- 成功交付确认本次订单对应的药效词，手册保留原符号与译义；不因一次成功揭示整套语言。
- 失败记录“该符号在此订单中不对应所交药效”，不自动揭示正确答案。
- 解谜依靠固定词义和交叉线索，不是每次来客重新随机答案。必要线索必须先于相应订单出现。
- 首版手册明示已开放药水的加工方法，让玩家主要破解“需要什么”，然后执行制药步骤。

**当天实现边界：**

只做两种族、三药水、两设施、单顾客、六个教学订单和后续重复经营。使用文字、简易图标和占位卡面；暂不做战斗、复杂背包、多人排队、倒计时催单、设施升级和完整语言语法。

Cocos采用一个主场景：桌面卡牌层、商店面板、手册侧栏、结算提示。实现职责建议为：

| 模块 | 职责 |
| --- | --- |
| GameController | 来客、经营、交付、结算的状态切换；金币与声誉 |
| CardView / DragController | 卡面显示、拖放、吸附与交付预览 |
| CraftingSystem | 配方匹配、加工计时、输入消耗和输出生成 |
| CustomerSystem | 订单序列、种族对白与药水结果判定 |
| HandbookSystem | 书页开放、词义猜测、成功确认与失败记录 |
| GameData | 卡牌、配方、词典、订单和线索配置；界面仅读取当前可见信息 |

首版优先配置驱动，词义真值与玩家猜测分开保存，便于后续添加种族、配方和订单。保存金币、声誉、库存、手册与订单进度；加工开始和完成时保存，加工中的任务恢复后重新计时，避免重复返还材料。

## 二、核心循环

**NPC来店 → 阅读未知需求 → 查阅手册并推断药效 → 花钱购买素材 → 堆叠加工并炼制 → 交付药水 → 结算与知识更新 → 下一位NPC。**

1. **来客与观察**：出现一张NPC卡，展示种族、未知文字和情境。首版不设催单时间，让玩家有时间思考。
2. **破译需求**：对照手册中的图像、符号重复和既往记录，形成药效猜测。例如线索画着伤者饮药后伤口愈合，旁边出现精灵符号A；当前NPC也使用A，玩家推断其需要治愈药。
3. **采购与规划**：查看库存和配方，购买缺失素材。商店购买后直接生成桌面卡牌；设施首版固定提供。
4. **分步制药**：先用研钵把药材加工为药粉，再把药粉与清水叠到炼药锅上，得到成品。加工顺序通过中间物自然约束。
5. **交付与结果**：
   - 成功：NPC恢复并离开，支付报酬；确认对应词义，在指定进度发放新的线索书页。
   - 失败：NPC死亡并移出桌面，药水消耗、不支付报酬、声誉下降；保留失败记录，继续接待下一位顾客。
6. **持续经营**：用收益补货，用新书页理解更多种族需求。已掌握订单提供稳定收入，陌生符号带来下一轮推理。

**首版经济与失败保护：**

- 每瓶药水材料成本3金币；成功基础报酬6金币。
- 使用交付前声誉计算报酬：声誉0—1时为5金币，声誉2—3时为6金币，声誉4—5时为7金币；结算后再恢复声誉。
- 声誉降至0仍可营业，首版不设置强制关店，满足失败后继续经营的体验。
- 当金币不足3且没有成品、在制药水或可完成一瓶药水的原料组合时，发放仅补足当前订单一瓶药水所需的应急素材，不发金币，也不直接提示正确药效；三种候选配方的缺料都补齐，避免救济泄露答案。每位顾客最多触发一次；结算后再检测下一单。
- 不允许无成本反复生成成品；失败保护只负责解除经营卡死，不替代正常采购。

**首轮内容节奏：**

| 阶段 | 来客与线索 | 玩家学习目标 |
| --- | --- | --- |
| 第1单 | 精灵治愈需求；开局页用明确图像关联符号与疗效 | 完成第一次猜词、采购、研磨、炼制与交付 |
| 第2—3单 | 精灵解毒、抗寒需求；开局页含对应可区分证据 | 理解同一种族符号稳定，熟悉三种药水 |
| 第4单 | 发放矮人线索页，再接待矮人治愈顾客 | 理解不同种族使用不同文字 |
| 第5—6单 | 矮人解毒、抗寒；线索页提供充分证据 | 对照图像和重复符号验证猜测 |
| 第7单起 | 发放补充对照页；重复出现已开放订单 | 复用知识、恢复声誉、持续经营 |

教学书页按接待进度发放，失败也不会阻断必需线索；成功仍带来即时词义确认。后续版本可把非必需的新书页作为成功奖励，但不能让未解订单等待自身成功后才获得必要线索。

**当天开发顺序与验收：**

先搭桌面与拖放，再打通一条制药配方和一位NPC结算；随后补齐商店、手册、另外两种药水及第二种族，最后补存档与失败保护。

验收以完整操作为准：可以从空闲状态接待NPC，查手册、买素材、完成两步制药并交付；正确药水带来金币和词义确认，错误药水导致NPC死亡与声誉下降；两种结果都能进入下一单。连续失败后仍可继续经营，刷新后可恢复已保存进度。

## 三、爽感来源

| 爽感来源 | 玩家体验 | 具体反馈 |
| --- | --- | --- |
| 看懂未知语言的顿悟 | “原来这个符号是解毒！” | 猜测被确认，符号旁出现译义，旧对白突然变得可读 |
| 推理得到现实验证 | “我的判断救了他。” | 顾客状态改善，付款与手册确认同时发生 |
| 手工炼制的完成感 | 原料经过自己的操作变成药水 | 卡牌吸附、加工进度、中间物变化、成品弹出 |
| 知识转化为经营优势 | 曾经棘手的顾客，如今一眼就懂 | 熟悉订单更快完成，误诊减少，收入和声誉恢复 |
| 新线索带来的期待 | 每次理解一点，又看到更大的未知 | 新书页引出另一种族符号，为下一次推理留下问题 |
| 失败后的纠正与翻盘 | “上次猜错了，这次我知道原因。” | 失败保留排除证据，经营可继续，后续成功证明学习有效 |

核心应落在“我通过理解陌生语言，亲手做出正确药水并救活顾客”。卡牌加工提供操作与产出的满足，经营让正确判断具有价值，手册则承载持续积累的知识。

首版试玩重点观察：玩家能否解释自己的推断依据；第一次成功是否产生顿悟；失败后是否知道下一次该检查什么。如果多数订单只能盲猜，优先改善线索，而不是增加配方或种族。
